# /idea — Capture a Command Central idea

When David shares an idea for Command Central (feature, module, improvement, or anything else), capture it as a GitHub Issue with proper labeling.

## How to use

David says something like:
- "I have an idea for a fitness module"
- "What if we added a journal feature?"
- "We should have notifications"
- "/idea dark mode toggle"

## What to do

1. **Ask clarifying questions** if the idea is vague — but keep it lightweight. One or two questions max. Don't over-interrogate. The goal is to capture the spark, not write a full spec.

2. **Create a GitHub Issue** with:
   - **Title**: Short, descriptive. Format: `Idea: <concise description>`
   - **Body**:
     - `## Idea` — 1-3 sentence summary of the concept
     - `## Context` — Why David mentioned it, what problem it solves (if discussed)
     - `## Open questions` — Things to figure out later
   - **Labels**: Apply the right combination:
     - `idea` — always
     - `module-idea` — if it's a new module (fitness, finance, journal, etc.)
     - `feature-idea` — if it's a feature within an existing module
     - `module: tasks` / `module: shell` / etc. — if it belongs to a specific module
     - `backlog` — unless David says it's urgent
   - Do NOT assign a priority label unless David explicitly says it's important/urgent

3. **Confirm** the issue was created and share the link.

## What NOT to do

- Don't start implementing the idea
- Don't create a feature branch
- Don't over-spec it — ideas are intentionally lightweight
- Don't add it to a project board unless asked
- Don't ask more than 2 clarifying questions — capture what you have and move on
